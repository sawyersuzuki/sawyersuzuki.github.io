Models
What am I looking at?

Each line is one model's forecast of daily population-weighted degree days for the region, all from runs that started at the same time. Where the lines sit close together the models agree; where they fan out, the atmosphere is in a state the models resolve differently, and that is where forecast risk lives.

  • Run time ("00Z", "12Z") is when the model started, in UTC. A day here runs from 06Z to 06Z, roughly midnight to midnight Central.
  • Normal is the 10-year average for that calendar date from ERA5. Observed is ERA5, or GFS analysis for the most recent week, which ERA5 has not reached yet.
  • Model range is the spread between different models. It is not an ensemble spread from one model, so it understates uncertainty when all models share the same blind spot.
  • Run-to-run change is what moves markets: the same days, re-forecast 12 hours later. Consistent revisions in one direction usually mean the pattern is still trending.

Totals are sums of daily degree days over forecast days 1-5, 6-10 and 11-15 after the run date. "vs normal" compares with the 10-year average for the same dates; "vs prev run" compares with the run 12 hours earlier over the same dates.

One fixed set of dates, forecast by each successive run. A line that keeps climbing means the models have been adding demand to the same days.

The last eight runs of one model, darkest is newest. Lines stacked on top of each other mean a stable forecast.

What am I looking at?

How wrong each model's regional degree-day forecast was, as a function of how far ahead it was made, scored against ERA5.

  • Mean absolute error is the typical size of the miss, in degree days per day. It grows with lead time; the lead at which it reaches the size of normal day-to-day variability is where the forecast stops adding much.
  • Bias is the average signed miss. A model with a positive HDD bias runs systematically cold in this region. Bias can be corrected; scatter cannot.
  • Caveat on fairness. ERA5 is produced with ECMWF's own model, and AIFS, GraphCast, Pangu, FourCastNet and Aurora were trained on ERA5. Scoring against ERA5 therefore flatters those models relative to scoring against weather stations. GFS-initialised runs also start from a slightly different analysis, which shows up as error at day 1.
  • Only days where ERA5 exists are scored, so the most recent week is excluded.

Forecast minus observed for each valid date at one lead time. Spikes shared by every model are days the atmosphere was hard to predict; a spike in one model is that model's bust.

What am I looking at?

How each model's forecast for a fixed extreme-weather window evolved as the event approached. This is the view that shows when the models "saw" an event and which saw it first.

  • The first chart holds the event dates fixed and moves the run date. Each point is one run's forecast of total degree days over the window. A model that reaches the observed line early, and stays there, gave useful warning.
  • The second chart shows daily values from runs made a chosen number of days before the event started.
  • Models only appear for events inside their archive: IFS open data starts in 2023 and AIFS in 2024, so 2021-22 events show GFS and the AI models NOAA re-ran.
  • Caveat. GraphCast, FourCastNet and Aurora were trained on years that include some of these events, so their hindcasts of them are not a clean test. Pangu-Weather (trained on 1979-2017) is out of sample for all of them.

Read left to right as time passing: 10 days out on the left, the day the event starts on the right.

What am I looking at?

Daily-mean 2 m temperature from the latest 00Z run of each model, on the same 0.5 degree grid. The regional numbers in the other views are population-weighted sums of exactly these maps.

  • Difference from model mean shows where one model is warmer (red) or colder (blue) than the average of the models shown. Large coherent patches are usually a disagreement about where a front or ridge sits, which matters more than scattered noise.
  • Temperature is centred on 65 F, the degree-day base: blue areas are accumulating heating degree days, red areas cooling degree days.
  • Hover a map for the value at a point. The Region and Measure filters above do not apply to maps.

What am I looking at?

Weather next to the prices it moves. All market data here comes from free public sources and arrives with a delay of a day to a week, so this view is for understanding relationships, not for trading signals.

  • Storage vs weather: each dot is one week. Weekly population-weighted HDD explains most of the weekly change in working gas in storage; the slope is roughly how many Bcf one extra HDD costs.
  • Henry Hub vs forecast revisions: the lower panel is the day-over-day change in the CONUS degree-day total for forecast days 1-15. Prices respond to changes in the forecast, not to the level of the forecast.
  • Power prices: day-ahead prices by zone against that region's degree days, where a free source exists.

Extending history

Run these in the repository. Backfill prints the download size, disk use and runtime and asks before it starts; it skips whatever is already stored.

wxcc update                                                  # latest runs + truth (the daily job)
wxcc backfill --model aifs --start 2025-01-01 --end 2025-03-31
wxcc backfill --model all --start 2024-01-05 --end 2024-01-20
wxcc query --model gfs --region TX --init 2026-11-15T00
wxcc build && wxcc serve                                     # rebuild and open this page
